# Jev compaction plugin: the Claude Code mod

This plugin uses Claude Code function hooks to replace a compaction with the
original messages, minus the tool calls and tool results Jev judged no longer
needed. `hooks/fast-jev.ts` is a thin adapter: it reads the plugin options,
finds the TypeSafe key, hands `session.compact` transcripts to the
`jev-compaction` library in `src/` (the plugin folder is the repository
root, so the hook imports it directly) and maps the result back onto session
messages. Your prompts are never touched; when trimming tool calls is not
enough, later stages archive whole old assistant steps to files, leaving one
marker row per run (see the options table in the top-level README). Jev is sent the whole
conversation as `state` (tool outputs replaced by a one-line note) and, for
every tool call outside the pinned first and newest messages, two questions:
whether the call should stay and whether its full output should stay. An
item is kept when Jev's probability reaches `keepThreshold`; a dropped result
is truncated to its first `truncateHeadChars` characters plus a one-line note,
and a dropped call disappears with its result.

The state is fitted into `maxStateTokens` in stages: tool inputs are
truncated, then long texts are abridged (oldest first, pinned messages last),
then old messages collapse to a `[… N chars omitted …]` note, then old tool
calls shrink to one line each, then old call-less messages are left out and
runs of old call-only messages fold together. Questions are split into as many requests as
needed so each request (state plus questions) stays under `maxRequestTokens`;
the full state is resent with every request. Token counts are estimated
without a tokenizer, calibrated to land a little above what Jev reports.

The mod is an early-access Claude Code function-hook module. The checked-in
type reference was generated by Claude Code **2.1.274**. Enable the function
hooks surface before installing or loading it:

```sh
export CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1
export TYPESAFE_API_KEY="<your TypeSafe key>"

claude plugin marketplace add Y-B-1/jev-compaction
claude plugin install jev-compaction@jev-compaction
```

For local development:

```sh
CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude --plugin-dir .
```

## Configuration

The plugin declares these `userConfig` values in
`.claude-plugin/plugin.json`:

| Option | Default |
| --- | ---: |
| `keepThreshold` | `0.15` |
| `keepCallThreshold` | `0.05` |
| `preserveRecentMessages` | `6` |
| `archiveResults` | `true` |
| `minReductionRatio` | `0.25` |
| `builtinFallback` | `auto` (`always`, `never`) |
| `maxStateTokens` | `25000` |
| `maxRequestTokens` | `60000` |
| `truncateHeadChars` | `150` |
| `resultPreviewChars` | `300` |
| `salvageChars` | `150` |
| `maxKeptResultChars` | `4000` |
| `inputTrim` | `true` |
| `hybridSummary` | `true` |
| `injectTrim` | `true` |
| `replyTrim` | `true` |
| `exchangeDrop` | `true` |
| `stepTrim` | `true` |
| `jevPruneBashOutput` | `false` |
| `jevPruneMinChars` | `4000` |
| `model` | `jev-latest` |

Nothing these stages cut is lost: each original is written to the archive
folder first and the marker left in its place names the file, so the model can
Read it back. Without `archiveResults` the three stages below do nothing.
On every compaction `replyTrim` archives whole old steps (replies, closed
tool runs, host-message rows) before the last prompt that Jev scores below
0.05. When trimming falls short, `injectTrim` folds old skill
bodies, element selections, pastes and long user rows beside the
notification fold, keeping any text typed around them. When that still falls
short, `exchangeDrop` replaces the work of old finished exchanges with one row
naming its archive, keeping the prompt. Each stage works on the best partial
result of the one before. When all of them still fall short, `stepTrim`
archives old steps by Jev score, then the lowest-scored steps of the current
task, until the minimum is met; prompt text is never changed. Subagent
transcripts are compacted the same way, against a target of
`minReductionRatio` of their own history. The hook returns `tokensBefore` and
`tokensAfter` to the engine.

When trimming frees less than the minimum and `builtinFallback` allows the
built-in summary, the hook first tries a hybrid (`hybridSummary`, on by
default): it splits the trimmed history at the earliest user turn whose tail
is at most 30% of the original history (less when the minimum is high), hands
only the part before it to the built-in summarizer (`next({ ...e, messages })`),
and returns that summary followed by the recent turns as trimmed. The split is
always at a user message with text, so no tool call is separated from its
result. When no user turn qualifies, the whole history goes to the built-in
summary as before.

Each compaction logs what the model reads before it, from Claude Code's own
Messages API view (`$.session.messages({ as: 'api' })`): estimated tokens of
user text, assistant text, thinking, tool inputs and tool results, and the
number of images. After a compaction that replaces the history it logs the
kept history's size against the original.

The TypeSafe key can be supplied as the sensitive `apiKey` plugin option or
through `TYPESAFE_API_KEY`. The environment variable is the recommended
development setup.

Every option except `apiKey`, `archiveResults`, `minReductionRatio`,
`jevPruneBashOutput`, `jevPruneMinChars`, `inputTrim`, `hybridSummary`, `injectTrim`, `replyTrim`, `exchangeDrop`, `stepTrim` and `model` is passed straight to the
library; see the root README for what they do. The `session.compact` hook runs the Jev requests concurrently. If Jev fails,
the response is malformed, the key is unavailable, the history cannot be
fitted into the state budget, or the estimated reduction is below
`minReductionRatio`, the hook logs a fallback and delegates to Claude Code's
built-in compaction. The minimum is measured against the real context that
`$.session.usage()` reports, not the history alone: the system prompt, tool
schemas and attachments count toward Claude Code's trigger but are never
compacted, so a cut of 25% of the history can free as little as 10% of the
context and the next compaction fires minutes later. When the history is too
small a share of the context to free the minimum even if all of it went, the
hook falls back without asking Jev. The outcome is one short toast; nothing is
written to the chat. The debug log (`claude --debug`) gets the reduction,
per-reason counts, state size and request count, and a per-call `decisions:`
line with both probabilities for diagnosis.
The plugin installs no compaction trigger of its own: compaction runs whenever
Claude Code compacts (its built-in auto-compact or a manual `/compact`), both
of which go through the `session.compact` hook.

## Scope and caveat

Function hooks are early access and may change between Claude Code releases.
This mod uses the generated declarations from 2.1.274 in
`types/claude-code.d.ts`; regenerate and review that file after a
Claude Code upgrade.
